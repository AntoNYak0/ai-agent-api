## 🔴 Критические проблемы (долг/техдолг)

### 1. `/summarize` KeyError
**Файл:** `app/prompts/micro.py`  
**Проблема:** `SUMMARIZE_PROMPT` не определён или используется `.replace("__MAX_LENGTH__")` без проверки существования.  
**Исправление:** 30 минут.

### 2. `/health/deep` тратит токены на UptimeRobot
**Файл:** `app/main.py:367-441`  
**Проблема:** UptimeRobot стучит каждые 5 минут → RPC вызовы к трём сетям.  
**Исправление:** Кэшировать результат `/health/deep` на 60 секунд, или разделить на `/health/deep/full` (дорогой) и `/health/deep/cached` (для мониторов). 1 час.

### 3. Отсутствие мониторинга цен на газ
**Проблема:** DirectFacilitator не учитывает цены на газ при приёме микроплатежей. При $0.0005 платеже газ Base может съесть всю маржу.  
**Решение:** Добавить `gas_price_threshold` — если gas > 50% от суммы платежа, отказывать с понятным сообщением. 2 часа.

### 4. Дублирование цен
**Файлы:** `app/pricing.py` и `app/mcp_server.py`  
**Проблема:** `UPTO_SERVICES` / `EXACT_SERVICES` дублируются в двух файлах. При изменении цены нужно править оба.  
**Решение:** Убрать дублирование из `mcp_server.py`, импортировать из `pricing.py`. 1 час.

## 🟡 Приоритетные доработки

### 5. ERC-8004: Регистрация сервера как агента
**Почему:** Claude Code через `agent-discovery-mcp` вызывает `find_agents_by_skill({ x402_only: true })` — если тебя нет в реестре ERC-8004, ты невидим для экосистемы.  
**Что сделать:**
- Зарегистрировать сервер в Identity Registry (`0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`)
- Заполнить метаданные: `x402Support: true`, endpoint, chainId: 8453, описание, цены
- Использовать `strands-erc8004` (PyPI) для Python-регистрации или `8004sdk` (npm)
- Проверить видимость через `8004scan.io` public API  
**Сложность:** Средняя. 1-2 дня (нужен небольшой скрипт + ETH на gas).

### 6. ERC-8257: Подготовка к реестру инструментов OpenSea
**Почему:** OpenSea запустил ERC-8257 — децентрализованный «магазин приложений» для AI-агентов. Инструменты регистрируются на цепочке, агенты автономно их находят и платят через x402.  
**Что сделать:**
- Изучить `@opensea/tool-sdk` — SDK для регистрации инструментов
- Задеплоить контракт Tool Registry с access predicates для каждого эндпоинта
- Интегрировать x402 как платёжный слой (уже готово!)
- Настроить цены: per-call через x402, subscription через ERC-20/NFT
**Сложность:** Высокая. 3-5 дней.

### 7. BNB Chain — поддержка x402 на BNB
**Почему:** Binance анонсировал x402 на BNB Chain (19 мая). Низкие комиссии, огромная аудитория.  
**Что сделать:**
- Добавить BNB Chain USDT/USDC контракты в `_NETWORK_ASSETS`
- Добавить BNB RPC в `DirectFacilitator`
- Обновить `NETWORKS` в `pricing.py`
- Протестировать приём платежей через BSC
**Сложность:** Низкая. 2-3 часа.

### 8. Улучшение модели «Upto» — честный биллинг
**Почему:** Модель Upto — главное нововведение x402 в 2026. Но текущая реализация считает цену как `base + tokens * rate`, что не учитывает фактическую сложность запроса.  
**Что сделать:**
- Добавить `complexity_multiplier` на основе фактического количества токенов ответа
- Если модель вернула < 500 токенов (простой запрос) — списывать меньше базовой ставки
- Если > 3000 токенов — списывать до максимума, но не больше
- Добавить `X-Actual-Cost` заголовок в ответ — прозрачность для клиента
**Сложность:** Средняя. 1 день.

### 9. Автоматическая выдача API-ключей после крипто-платежа

## 🟢 Стратегические улучшения

- Может привлечь аудиторию из РФ/СНГ, которая уже использует TON
**Сложность:** Средняя. 2-3 дня.

### 11. Apify Actor — второй канал дистрибуции
**Почему:** Apify официально не блокирует авторов из РФ. Pay-Per-Event модель: actor-start ($0.10), task-completed ($0.40), api-call ($0.05). Готовая аудитория разработчиков.  
**Что сделать:**
- Упаковать ключевые эндпоинты как Apify Actor
- Ценообразование: `await Actor.charge('task-completed', count=N)`
- Кросс-промо: на лендинге Apify → ссылка на standalone сервер
**Сложность:** Средняя. 1-2 дня.

### 12. Сжатие контекстного окна при 80% заполненности
**Требование из задачи:** Автоматически сжимать окно при 80% заполненности.  
**Что это значит практически:** Сервер взаимодействует с DeepSeek V4 (1M контекст). При отправке больших запросов (аудит кода, рефакторинг) нужно следить за размером контекста.  
**Реализация:**
- В `deepseek.py`: перед отправкой запроса считать токены (через tiktoken или оценочно `chars/4`)
- Если `estimated_tokens > 800K` (80% от 1M), применять компрессию:
  - Для кода: обрезать длинные строки, заменить повторяющиеся блоки на `[...]`
  - Для логов: оставить первые/последние 30% + ошибки
  - Для текста: суммаризировать через более дешёвую модель (deepseek-v4-flash)
- Добавить заголовок `X-Context-Compressed: true` когда применена компрессия
**Сложность:** Низкая. 2-3 часа.

### 13. Конкурентный анализ: снижение цен
**Проблема:** Рынок x402 падает (с $5.15M до $1.1M/мес). При текущих ценах ($0.0005–$1.00) микроплатежи могут быть дороже конкурентов.  
**Анализ:**

## 🛡️ Безопасность (из новостей)

### 16. Защита от supply-chain атак на MCP инструменты
**Проблема:** Исследования (Google, Socket) показали, что вредоносное ПО может внедрять скрытые команды в AI-инструменты и перенаправлять средства.  
**Решение:**
- Валидация `payment_tx` перед обработкой: проверять, что хэш транзакции соответствует ожидаемому формату (0x + 64 hex)
- Добавить лимит на сумму списания: никогда не списывать больше, чем `max_price`
- Санитайзинг всех входных параметров MCP инструментов (prompt injection через параметры)
**Сложность:** Низкая. 2-3 часа.

### 17. Усиление защиты от prompt injection
**Сейчас:** 10 regex паттернов в `deepseek.py:_sanitize()`.  
**Добавить:**
- Проверку на попытки переопределения системного промпта через пользовательский ввод
- Фильтрацию попыток jailbreak (DAN, "ignore previous instructions", и т.д.)
- Логирование попыток инъекций для анализа атак
- Rate-limit на повторные попытки инъекций от одного IP
**Сложность:** Низкая. 2-3 часа.

## 🚫 Что НЕ делаем (и почему)

- ❌ **Stripe MPP** — Stripe ушёл из РФ, невозможен легальный онбординг
- ❌ **Azure Marketplace** — ограничения для РФ, enterprise-клиенты под санкциями
- ❌ **Virtuals ACP** — требует KYC/верификацию личности, риски для РФ
- ❌ **Размещение на agentic.market** — домен заблокирован, требует CDP + KYC
- ❌ **Свой токен/ICO** — юридические риски в РФ, отсутствие регулирования
- ❌ **Сложный смарт-контракт для ERC-8004** — есть готовые SDK (`strands-erc8004`, `8004sdk`), не изобретать велосипед

## 🎯 North Star: что строим

**AI Agent API** — это суверенный x402-совместимый сервер для AI-агентов, который:

1. **Находится** через ERC-8004 реестр (идентичность)
2. **Оплачивается** через x402 (USDC на Base/Arbitrum/Optimism/BNB + USDT на Tron/TON)
3. **Регистрируется** в ERC-8257 как инструмент для AI-агентов
4. **Принимает** оплату через API-ключи (для людей) и x402 (для машин)
5. **Зарабатывает** на разнице между DeepSeek API ($0.0014/1K) и розничной ценой ($0.003/1K)
6. **Масштабируется** через Apify + TON + прямые продажи

Ключевое преимущество перед конкурентами: **реально работающий x402 paywall** (большинство конкурентов только декларируют `x402Support: true` без фактической платёжной стены).
