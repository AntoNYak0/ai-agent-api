Путь 1: Быстрый старт с фасилитатором Coinbase

Это самый простой способ начать принимать платежи. Вы настраиваете только свой API-сервер, а всю «грязную» работу с блокчейном (проверку и проведение транзакций) передаете сервису-посреднику — фасилитатору. Coinbase предоставляет публичный фасилитатор с щедрым бесплатным лимитом.

Плюсы: Не нужно поднимать свою блокчейн-инфраструктуру, управлять приватными ключами и беспокоиться о комиссиях за газ.
Минусы: Зависимость от стороннего сервиса и комиссия при превышении лимита (1000 транзакций/мес бесплатно, далее $0.001 за транзакцию).
Пошаговая настройка сервера-продавца

    Определите цену и параметры. Решите, сколько будет стоить доступ к вашему ресурсу, в какой сети вы будете принимать платежи (для тестов рекомендуется base-sepolia, для реальных платежей — base) и на какой адрес кошелька будут поступать средства.

    Настройте сервер. Ваш сервер должен «охранять» платный контент и при обращении без оплаты возвращать HTTP-статус 402 Payment Required с инструкцией к оплате.

    Для сервера на Node.js (Express/Hono)
    Самый простой способ — использовать готовое middleware, например, x402-express или x402-hono. Эти пакеты автоматически генерируют правильный ответ 402 и взаимодействуют с фасилитатором.
    javascript

    // Пример концепции middleware для Hono
    import { Hono } from 'hono';
    import { paymentMiddleware } from 'x402-hono'; // Условное название

    const app = new Hono();

    // Применяем middleware к платному эндпоинту
    app.use('/api/premium-data', paymentMiddleware({
      // Ваш адрес для получения средств
      receiverAddress: '0xYourWalletAddress',
      // Настройки цены и сети
      price: '$0.10',
      network: 'base-sepolia',
      // URL фасилитатора (публичный от Coinbase)
      facilitatorUrl: 'https://x402.org/facilitator'
    }));

    app.get('/api/premium-data', (c) => {
      return c.json({ data: 'Секретные данные для платящих агентов!' });
    });

    Для сервера на Python
    Вы можете реализовать логику самостоятельно. Вот как будет выглядеть обработка запроса:

        При получении запроса на платный эндпоинт проверьте, есть ли в нем платежный заголовок X-PAYMENT.

        Если заголовка нет, верните ответ со статусом 402 и JSON-телом, содержащим требования к оплате: сеть, адрес получателя, сумму и контракт токена.

        Если заголовок X-PAYMENT присутствует, извлеките из него подписанные данные и отправьте их на верификацию фасилитатору.

    Проверка и зачисление платежа. Когда клиент присылает повторный запрос с заголовком PAYMENT-SIGNATURE, ваш сервер (или middleware) выполняет два действия:

        Отправляет POST /verify на URL фасилитатора (https://x402.org/facilitator/verify), чтобы проверить подлинность подписи клиента.

        После успешной проверки отправляет POST /settle, чтобы фасилитатор провел саму транзакцию в блокчейне.
        Только после этого вы отдаете клиенту платный контент, а в ответ добавляете заголовок PAYMENT-RESPONSE с подтверждением.

🏰 Путь 2: «Суверенный» режим (Sovereign Mode)

Этот путь для тех, кто хочет полного контроля и независимости от сторонних сервисов. В этом режиме ваш сервер сам выступает в роли фасилитатора: он напрямую подключается к блокчейн-ноде, проверяет транзакции и, при необходимости, сам их отправляет.

Плюсы: Полная автономия, отсутствие комиссий посредников, повышенная безопасность за счет собственной инфраструктуры.
Минусы: Требует глубоких технических знаний, управления приватными ключами, оплаты комиссий за газ и поддержки инфраструктуры (нода, база данных для защиты от повторных атак).

Вот как это работает на примере блокчейна Rootstock, но принцип подходит для любой EVM-сети (Ethereum, Base и др.).
Ключевые компоненты «суверенного» сервера

    Прямое подключение к блокчейну: Ваше приложение использует библиотеку (например, web3.js для JavaScript или viem) для подключения к собственной или публичной RPC-ноде блокчейна.

    Защита от повторных атак (Idempotency): Чтобы один и тот же чек об оплате нельзя было использовать дважды, вам нужна база данных (обычно Redis). Она хранит идентификаторы всех успешных транзакций и блокирует повторные.

    Собственный фасилитатор (опционально): Если вы хотите не только проверять прямые переводы, но и принимать платежи в токенах по стандартам EIP-3009 или Permit2, вам понадобится поднять свой фасилитатор. Пакет @x402-sovereign/core позволяет сделать это в несколько строк кода.
    javascript

    // Пример с @x402-sovereign/core и Express
    import express from "express";
    import { Facilitator, createExpressAdapter } from "@x402-sovereign/core";
    import { baseSepolia } from "viem/chains";

    const app = express();
    app.use(express.json());

    // Инициализируем своего фасилитатора с вашим приватным ключом
    const facilitator = new Facilitator({
      evmPrivateKey: process.env.EVM_PRIVATE_KEY, // Приватный ключ для проведения платежей
      networks: [baseSepolia],
    });

    // Создаем стандартные эндпоинты фасилитатора
    createExpressAdapter(facilitator, app, "/facilitator");

    // Теперь URL вашего фасилитатора: http://localhost:3000/facilitator
    // Вы указываете его в своем платежном middleware

Этапы обработки платежа в «суверенном» режиме

    Запрос (Challenge): Клиент запрашивает /api/premium. Сервер видит, что нет заголовка X-Payment, и отвечает 402, указывая в теле ответа адрес кошелька, сумму в токенах и сеть.

    Оплата клиентом: Клиент самостоятельно создает и отправляет транзакцию в блокчейн, используя данные из ответа 402.

    Подтверждение (Proof): Клиент повторяет запрос к вашему API, но теперь добавляет заголовок X-Payment с хешем своей транзакции.

    Проверка (Settlement): Ваш сервер получает хеш, идет в блокчейн и проверяет:

        Существует ли такая транзакция и была ли она успешна?

        Совпадает ли адрес получателя в транзакции с вашим?

        Достаточна ли сумма?

        Не использовался ли этот хеш раньше (проверка по Redis)?
        Если все проверки пройдены, хеш сохраняется в Redis, а клиент получает доступ к контенту.

💡 Продвинутая техника: Динамическое ценообразование

Особенно актуально для ИИ-сервисов. Вместо фиксированной платы вы можете выставить счет по факту потребления с помощью схемы upto.

Логика такая:

    Клиент авторизует максимальную сумму (например, до $0.10).

    Сервер выполняет работу (например, генерацию ответа от ИИ) и подсчитывает реальную стоимость (например, $0.00001 за токен).

    При расчете (settle) сервер списывает точную сумму за фактически потраченные ресурсы, не превышая лимит клиента.

Это делает бизнес-модель честной и прозрачной: клиент платит только за то, что реально использовал.
